Seção 1 — O que é o Docker e por que usar
💡
Entendendo o conceito

Imagine que cada serviço do HealthSys precisa de um ambiente exato para funcionar: Java 17, variáveis de ambiente, porta de rede, banco de dados. Configurar tudo isso manualmente em cada máquina é trabalhoso e sujeito a erros.

O Docker resolve isso criando containers — ambientes isolados e portáteis que empacotam o serviço e tudo que ele precisa. O que roda na sua máquina é idêntico ao que vai rodar em produção.

Analogia simples Pense num container como uma "caixa lacrada" contendo o programa + todas as suas dependências. Você só precisa dizer "abra essa caixa" e ela roda — sem instalar nada manualmente.
🏗️
Arquitetura do HealthSys no Docker
Rede interna Docker (healthsys_default)
┌─ postgres:5432 ← banco de dados compartilhado
├─ zookeeper:2181
├─ kafka:9092 ← mensageria async
├─ user-service:8081
├─ patient-service:8082
├─ triage-service:8083
├─ record-service:8084
├─ bed-service:8085
└─ api-gateway:8080 ← único ponto exposto ao frontend
↑ Você (frontend / Postman) acessa apenas localhost:8080
Seção 2 — Instalando o Docker Desktop
1

Baixe o instalador

Acesse docker.com/products/docker-desktop e clique em "Download for Windows".

2

Execute o instalador

Abra o arquivo baixado (Docker Desktop Installer.exe). Mantenha as opções padrão e clique em Ok até finalizar.

WSL 2 obrigatório no Windows O instalador pode pedir para ativar o WSL 2 (Windows Subsystem for Linux). Aceite e reinicie o computador quando solicitado. O Docker não funciona sem ele.
3

Inicie o Docker Desktop

Após a instalação, abra o Docker Desktop pelo menu Iniciar. Aguarde o ícone da baleia 🐳 aparecer na barra de tarefas (canto inferior direito).

Docker pronto quando: O ícone da baleia fica parado (sem animação) e o app mostra "Docker Desktop is running".
4

Verifique a instalação

Abra o terminal (PowerShell ou CMD) e execute:

PowerShell
docker --version
Docker version 27.x.x, build xxxxxxx

docker-compose --version
Docker Compose version v2.x.x

Se aparecer as versões, está tudo instalado corretamente.

Seção 3 — Rodando o HealthSys pela primeira vez
⏱ Tempo estimado: 10–20 minutos na primeira vez O Docker precisa baixar as imagens base (Java, PostgreSQL, Kafka) e compilar todos os serviços. Das próximas vezes leva menos de 1 minuto.
1

Confirme que o Docker Desktop está rodando

O ícone 🐳 deve estar na barra de tarefas sem animação. Sem isso, os comandos abaixo falham.

2

Abra o terminal na pasta do projeto

No Windows Explorer, navegue até a pasta healthsys, clique com o botão direito em qualquer área vazia e selecione "Abrir no Terminal". Ou abra o PowerShell/Git Bash e navegue:

PowerShell / Git Bash
cd C:\Users\seu-usuario\IdeaProjects\healthsys
3

Execute o comando de build e start

Terminal — dentro de healthsys/
docker-compose up --build

O --build instrui o Docker a compilar os JARs antes de subir. Necessário apenas na primeira vez ou quando o código mudar.

4

Acompanhe os logs no terminal

Você verá muitas linhas rolando. Isso é normal. O processo passa por 3 fases:

5

Confirme que tudo subiu

Quando aparecer "Started XxxApplication" para todos os serviços, o sistema está pronto. Abra outra aba do terminal e execute:

Se algo não funcionar, os logs mostram o erro. Há duas formas:

A

Pelo Docker Desktop

Clique no nome do container na lista → aba Logs.

B

Pelo terminal

# Ver logs de um serviço específico:
docker-compose logs user-service

# Acompanhar logs em tempo real (Ctrl+C para sair):
docker-compose logs -f user-service

# Ver logs de todos os serviços:
docker-compose logs -f
Seção 5 — Uso do dia a dia
🚀
Subir o sistema (sem mudanças de código)
docker-compose up
# Sem --build: usa os containers já compilados. Muito mais rápido.
Você pode adicionar -d para rodar em background e liberar o terminal:
docker-compose up -d
🔨
Subir após mudança de código
# Recompilar e subir todos:
docker-compose up --build

# Recompilar apenas o serviço alterado (mais rápido):
docker-compose up --build user-service
🛑
Parar o sistema
# Parar tudo (dados do banco preservados):
docker-compose down

# Parar E apagar o banco (volta ao zero):
docker-compose down -v

# Ou simplesmente Ctrl+C no terminal onde está rodando
Cuidado com o -v Ele apaga o volume postgres_data — todos os dados do banco são perdidos. Use apenas para resetar o ambiente.
🔄
Reiniciar um serviço específico
docker-compose restart user-service
🧹
Liberar espaço em disco
# Remove containers parados, imagens sem uso e cache de build:
docker system prune

# Versão mais agressiva (remove tudo não utilizado):
docker system prune -a
Seção 6 — Testando a API após subir
Todas as chamadas vão para localhost:8080 (API Gateway) Nunca chame as portas 8081–8085 diretamente do frontend — elas são internas.
🔑
Passo 1 — Fazer login e pegar o token
curl / PowerShell / Postman
# curl (Git Bash / Linux):
curl -X POST http://localhost:8080/api/auth/login \
-H "Content-Type: application/json" \
-d '{"email":"admin@healthsys.com","password":"admin123"}'

# Resposta esperada:
{"token":"eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhZG1..."}

Passo 2 — Usar o token nas próximas chamadas
# Listar pacientes usando o token:
curl http://localhost:8080/api/patients \
-H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."
Dica: use o Postman É muito mais fácil do que curl. Crie uma variável token, cole o valor retornado pelo login, e use Bearer {{token}} em todas as requisições.

Seção 7 — Problemas comuns e soluções
❌ "Cannot connect to the Docker daemon" O Docker Desktop não está aberto. Abra o app e aguarde a baleia parar de animar.
❌ "Port is already allocated" / "address already in use" Alguma porta (5432, 8080, etc.) já está sendo usada por outro programa. Soluções:

docker-compose down para garantir que não há containers antigos rodando.
Ou verifique e feche o programa que usa a porta (ex: PostgreSQL local na porta 5432).
❌ Serviço fica reiniciando (Restarting) O serviço travou ao iniciar. Veja os logs para o erro real:
docker-compose logs nome-do-servico
❌ "Connection refused" ao chamar localhost:8080 O api-gateway ainda não terminou de subir. Aguarde todos os "Started XxxApplication" aparecerem nos logs. O gateway é o último a subir.
❌ Build demora mais de 20 minutos ou trava Pode ser limite de memória. No Docker Desktop vá em:
Settings → Resources → Memory → aumente para pelo menos 4 GB.
⚠️ Mudei o código mas o comportamento não mudou Você precisa reconstruir o container. Execute:
docker-compose up --build nome-do-servico
♻️
Reset completo do ambiente

Se algo estiver muito errado e quiser começar do zero:

# Para tudo e apaga volumes (banco zerado):
docker-compose down -v

# Remove imagens antigas para forçar redownload:
docker-compose down --rmi local

# Sobe tudo do zero:
docker-compose up --build
