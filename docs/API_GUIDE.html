Seção 1 — Autenticação & Fluxo JWT

1

Login — obtenha o token

Faça um POST /api/auth/login com email e senha. A resposta contém o JWT válido por 10 horas.

2

Inclua o token em todas as requisições

Adicione o header Authorization: Bearer <token> em cada chamada à API (exceto o próprio login).

3

Gateway valida o token

O API Gateway intercepta a requisição, valida a assinatura JWT e injeta o header X-User-Email para os serviços internos.

4

Serviço responde

O microserviço recebe a requisição já autenticada e processa normalmente.

Base URL em produção (Docker) Todas as chamadas do frontend devem apontar para o API Gateway: http://localhost:8080.
Os serviços individuais (8081–8085) ficam na rede interna Docker e não precisam ser acessados diretamente.

Seção 8 — Códigos de Erro HTTP

Código Status Causa mais comum O que fazer
400 Bad Request Body inválido ou campo obrigatório ausente Revise os campos obrigatórios da requisição
401 Unauthorized Token JWT ausente, expirado ou assinatura inválida Faça login novamente e use o novo token
403 Forbidden Credenciais corretas mas perfil sem permissão Verifique o perfil do usuário
404 Not Found Recurso não encontrado (ID inexistente) Confirme o ID enviado
500 Internal Server Error Erro inesperado no servidor (ex.: banco fora do ar) Verifique os logs do serviço correspondente
Dica — Identificando qual serviço retornou o erro Como todas as chamadas passam pelo API Gateway (:8080), o erro HTTP retornado reflete o status do microserviço de destino. Use os logs de cada container (docker logs <container>) para diagnóstico detalhado.
